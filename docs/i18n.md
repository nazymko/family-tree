# Interface languages

The app has 21 interface languages: English, Ukrainian and 19 more. This page says who maintains which, how a missing
translation is handled, and how to run the job that translates the rest.

## Policy

- **English (`app/src/lib/i18n/en.ts`) is the source of truth.** It is complete and defines the shape of every catalogue.
- **Ukrainian (`uk.ts`) is complete.** The tests demand it (`check-i18n.test.ts`, `be.test.ts`).
- **Feature work maintains only English and Ukrainian.** Add every new string to both, and nothing else.
- **Every other language is a partial catalogue** in `app/src/lib/i18n/locales/<code>.ts`. Any key it lacks falls back to English,
  key by key. These files are written by the translation job (below), not by hand during feature work.
- **No Russian.** There is no Russian catalogue and none may be added.
- In every language, "family tree" means a genealogy: use the normal genealogy word (Ukrainian: «родовід»), not a plant tree.

The partial languages are: `zh-Hans` 中文简体, `hi` हिन्दी, `es` Español, `ar` العربية (right to left), `fr` Français,
`bn` বাংলা, `pt` Português, `id` Bahasa Indonesia, `ur` اردو (right to left), `de` Deutsch, `ja` 日本語, `mr` मराठी,
`vi` Tiếng Việt, `te` తెలుగు, `ha` Hausa, `tr` Türkçe, `sw` Kiswahili, `tl` Filipino, `ta` தமிழ்.

## How the fallback works

- `t(key)` looks in the active language, then in English. A raw key is never shown when English has it.
- `plural(key, n)` picks the category with `Intl.PluralRules(<language tag>)`. If the language has the key but not that
  category, it uses its own `other` form. If the language lacks the key, it uses English with English rules.
- A partial catalogue is loaded with a dynamic `import()` when the language is chosen (one chunk per language, nothing
  extra in the main bundle). Until the chunk lands, English shows; the screen updates by itself when it does.
- `setLanguage()` also sets `<html lang>` (the BCP-47 tag: `fil` for Filipino, `zh-Hans` for Chinese) and `<html dir>`
  (`rtl` for Arabic and Urdu).
- `LANGUAGES` (in `locale.svelte.ts`) lists the languages: English, Ukrainian, then the rest by code. Settings shows
  a partial language as `Español — 12 %` (its share of the English keys).
- **System language.** `resolveSystemLanguage` goes through the navigator languages in order and takes the first that is English,
  Ukrainian or a partial catalogue at least 50 % translated (`AUTO_PICK_MIN_PERCENT`); otherwise English. Mapping: `zh`,
  `zh-CN`, `zh-Hans-*` to `zh-Hans` (Traditional Chinese is not offered), `pt-BR` to `pt`, `fil` to `tl`. A user can always
  choose a language that is less translated in Settings.
- The Rust `Language` enum (`crates/gt-session/src/dto.rs`) lists the same codes; add a code in both places.

## What is stored for a translation

- `locales/<code>.ts`: the translated keys (`export default` a `PartialMessages`).
- `locales/<code>.meta.json`: for every translated key a hash of the English text it was made from. When English changes, the key is
  reported as **stale** by `i18n-missing` until it is translated again.
- `locales/coverage.json`: the share (percent) per language, written by `i18n-apply`; the picker and the 50 % rule read it.

## Running the translation job

Tools (Node, no install needed):

```
node scripts/i18n-missing.mjs                         table: translated / stale / missing per language
node scripts/i18n-missing.mjs --locale es             one language, the first missing keys
node scripts/i18n-missing.mjs --locale es --json      all missing and stale keys with English and Ukrainian text, for a translator
node scripts/i18n-missing.mjs --locale es --json --section nav --limit 100     a slice
node scripts/i18n-apply.mjs es translations.json      merge translations (checks them, updates the hashes and coverage)
```

`translations.json` is a flat object from key to text, for example
`{"nav.family": "Familia", "common.people": {"one": "{n} persona", "many": "{n} de personas", "other": "{n} personas"}}`.
`i18n-apply` rejects a key that is not in English, a different `{placeholder}` set, an empty text, and plural forms that are
not exactly the CLDR categories of the language (`ja`: `other`; `es`, `fr`, `pt`: `one`, `many`, `other`; `ar`: `zero`, `one`,
`two`, `few`, `many`, `other`). In a plural entry a special form (`one`, `two`, `zero`) may leave out `{n}`; `other` must keep it.
The other keys of the file are still applied, and the exit code is 2.

Tests: `node --test "scripts/*.test.mjs"` (the tools), `npx vitest run src/lib/i18n` in `app/` (fallback, direction, every
locale file only has keys English has, with the same placeholders).

The step-by-step job is the project skill `.claude/skills/translate-missing/SKILL.md`.
